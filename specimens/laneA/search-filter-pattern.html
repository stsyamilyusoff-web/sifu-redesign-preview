Search + Filter · the pattern

How a tutor narrows the Requests feed (the North Star surface). Grounded in the live feed + the locked Wave-1 filter set; composes Lane B's SearchField + FilterChips (field shape follows Lane B's fork C when decided).

The rules

1
Search narrows, filter structures. the search field matches text within results; structured narrowing lives in the filter sheet. Both always co-exist on the feed.
2
Filters = the validated set. Subject · Level · Mode · Your areas (the locked Wave-1 set). The funnel glyph carries an active-count badge; applied filters echo as removable indigo chips under the search field.
3
The sheet keeps context + shows honest counts. filter sheet uses sheetPull; the CTA is always “Show N requests” (live count, Airbnb pattern) so a tutor never files into an empty result.
4
Adaptive social proof. encourage when competition is low (“Be the first to apply”); soften or hide the count when high. A discouraging “25 applied” never shows (strategy §8).
5
Low-supply keeps tutors engaged. no-fit-results offers notify-me, widen areas, add subjects, browse all, never a dead end (strategy §8). Hard misfits (wrong gender/mode) are hidden by filters, not flagged.
