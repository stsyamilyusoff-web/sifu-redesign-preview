Notification & banner · the pattern

How the app talks to the tutor. Grounded in the live surfaces (Notifications centre, NotificationPreferences, deep-link screens, permission/drip banners) + the strategy's high-fit push loop.

The rules

1
Four surfaces, one job each. toast = confirms an action just taken (auto-dismiss, toastSlide) · banner = a state needing attention (persists until resolved/dismissed) · push = brings the tutor back · centre = the durable history. One message lives on ONE surface, never duplicated.
2
One banner at a time, highest wins. banners never stack; priority order: account-blocking (unverified) > permission > drip prompts. Amber = the one check-this flag; red only for hard blockers.
3
Push = high-fit + operational only. the high-fit request alert is THE return-and-apply loop (strategy §8), fed by notify-me + match criteria; plus class reminders and application decisions. Never promotional spam; neutral copy; respects NotificationPreferences.
4
Every push deep-links to the actionable screen. request alerts land on the request detail; class reminders on the class (the live deep-link screens already exist). Never the home screen.
5
The centre catches everything. every push/banner event is also a row in Notifications (bell + count badge), so nothing is missable; read state syncs the badge.
