State system · the four-state rulebook

The cross-cutting pattern every screen follows. Grounded in the live app (30 skeleton vs 13 spinner screens = today's split) and the references (content-shaped loading, friendly empties, celebratory success).

The rules

1
Every screen declares all four states. loading · empty · error · success paths are designed, never left to chance.
2
Loading = content-shaped skeleton. skeletons mirror the layout they replace. Spinners are allowed ONLY inside a busy button. Fixes the live 30-skeleton / 13-spinner split.
3
Empty = friendly + one action. tinted icon circle + title + one line + ONE next action. Never a blank screen or bare text.
4
Error = human message + retry. never render a raw error string; route through one friendly-message chokepoint. Always offer Retry.
5
Success = a moment, varied by design. key wins get the celebratory treatment (motion decision); success screens stay intentionally varied, unified only by a quality floor: icon + clear title + what happens next + one action, calm copy, no gambling hype.
